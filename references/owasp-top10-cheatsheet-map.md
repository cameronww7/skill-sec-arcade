# OWASP Top 10 (2025) → Cheat Sheet Series map

Quick lookup for `dungeon-crawl-threat-map`. Each row: the category, what it actually means in plain language, and the OWASP Cheat Sheet Series sheets that give concrete remediation guidance. Cite the sheet by name, don't guess a URL unless you're confident of the exact slug. The reader can search `cheatsheetseries.owasp.org` for the name directly.

This is the OWASP Top 10:2025 Web Application Security Risks edition (released November 2025, finalized January 2026), the first update since 2021. If a codebase or report you're reading still cites the 2021 numbering, note the mapping: 2021's A10 SSRF is now folded into 2025's A01, 2021's A06 Vulnerable Components is now split out as 2025's A03, and several categories re-ranked without changing name.

| Category | Plain language | Relevant Cheat Sheets |
|---|---|---|
| A01: Broken Access Control | Users can do or see things they shouldn't, because the app didn't check permissions properly. Now also covers Server-Side Request Forgery (SSRF), the server being tricked into making requests to unintended destinations on the attacker's behalf, folded in from the old A10:2021. | Authorization Cheat Sheet, Access Control Cheat Sheet, Insecure Direct Object Reference Prevention Cheat Sheet, Server-Side Request Forgery Prevention Cheat Sheet |
| A02: Security Misconfiguration | Default credentials, verbose error messages, unnecessary features enabled, missing security headers. Moved up from #5 in 2021 to #2, now the second most common issue in the data. | Security Headers Cheat Sheet, Docker Security Cheat Sheet, Attack Surface Analysis Cheat Sheet |
| A03: Software Supply Chain Failures | New category for 2025. An expansion of the old "vulnerable and outdated components" idea to cover the whole supply chain: build pipelines, package registries, and dependency provenance, not just an out-of-date library version. | Software Supply Chain Security Cheat Sheet, Vulnerable Dependency Management Cheat Sheet |
| A04: Cryptographic Failures | Sensitive data (passwords, tokens, PII) is exposed because it wasn't encrypted, was encrypted weakly, or keys were mishandled. | Cryptographic Storage Cheat Sheet, Transport Layer Security Cheat Sheet, Password Storage Cheat Sheet |
| A05: Injection | Untrusted input gets interpreted as code or commands instead of data (SQL, OS commands, LDAP, etc). | SQL Injection Prevention Cheat Sheet, OS Command Injection Defense Cheat Sheet, Injection Prevention Cheat Sheet |
| A06: Insecure Design | The vulnerability is baked into how the feature was designed, not a coding mistake: a missing authorization check that was never designed in, no rate limit on a password reset flow, a trust boundary with no control guarding it. Can't be patched after the fact the way a bad line of code can, it's embedded in the workflow itself. Notable CWEs: CWE-501 (Trust Boundary Violation), CWE-269 (Improper Privilege Management), CWE-434 (Unrestricted Upload of File with Dangerous Type). This is the category `dungeon-crawl-threat-map` is built to catch: it has no bad pattern for a scanner to match, only reasoning about the architecture surfaces it. | Threat Modeling Cheat Sheet |
| A07: Authentication Failures | Login, session, or credential handling is weak, allowing account takeover or session hijacking. | Authentication Cheat Sheet, Session Management Cheat Sheet, Credential Stuffing Prevention Cheat Sheet, Multifactor Authentication Cheat Sheet |
| A08: Software and Data Integrity Failures | Code or data is trusted without verifying it hasn't been tampered with, e.g. unsigned auto-updates, insecure deserialization. | Deserialization Cheat Sheet |
| A09: Security Logging and Alerting Failures | Attacks go undetected because nothing logs suspicious activity or alerts on it in time to act. Renamed from "Monitoring" to "Alerting" for 2025, emphasizing that a log nobody's alerted on doesn't help during an incident. | Logging Cheat Sheet, Application Logging Vocabulary Cheat Sheet |
| A10: Mishandling of Exceptional Conditions | New category for 2025, replacing SSRF (which moved into A01). Covers improper error handling, logical errors, failing open instead of closed, and unchecked return values, cases where the system does the wrong thing under an unexpected condition instead of failing safely. | Error Handling Cheat Sheet |
