# OWASP Top Ten Projects (full catalog)

"OWASP Top Ten" is not one list, it's a family of roughly two dozen domain-specific Top Ten projects. The one most people mean by default, and the only one currently wired into any skill in this plugin (`references/owasp-top10-cheatsheet-map.md`, used by `dungeon-crawl-threat-map`), is the **Top 10 Web Application Security Risks**. This file catalogs the rest of the family: API, mobile, Kubernetes, CI/CD, business logic, and more.

**This is a static reference only.** Nothing in this plugin consumes it yet, it's documented here so the full family is on record for a future skill that wants to cite a domain-specific list (e.g. a Kubernetes-heavy repo citing the Kubernetes Top Ten, an API-heavy repo citing the API Security Top 10) instead of stretching the Web Application list to cover things it was never scoped for.

## Active (numbered list published, real content)

1. Top 10 Web Application Security Risks (2025) - A standard awareness document representing broad consensus on the most critical security risks to web applications. - https://owasp.org/www-project-top-ten/
2. API Security Top 10 (2023) - Identifies and documents the security risks specific to APIs, which many organizations expose without rigorous security testing. - https://owasp.org/www-project-api-security/
3. LLM Applications Top 10 (2025) - Identifies the most critical security vulnerabilities in LLM applications; now maintained under the OWASP GenAI Security Project. - https://owasp.org/www-project-top-10-for-large-language-model-applications/
4. Top 10 CI/CD Security Risks (2022) - CI/CD environments, processes, and systems are the beating heart of any modern software organization. - https://owasp.org/www-project-top-10-ci-cd-security-risks/
5. Mobile Top 10 (2024) - A data-driven list of the top ten security risks in mobile applications, refreshed for 2024. - https://owasp.org/www-project-mobile-top-10/
6. Kubernetes Top Ten (2025) - When adopting Kubernetes, we introduce new risks to our applications and infrastructure. - https://owasp.org/www-project-kubernetes-top-ten/
7. Top 10 Infrastructure Security Risks (2024) - Provides information on the top infrastructure security risks, threats, and vulnerabilities, focused on internal compromise after initial access. - https://owasp.org/www-project-top-10-infrastructure-security-risks/
8. Top 10 for Business Logic Abuse (2025) - Modern applications rely heavily on complex business logic to manage workflows, data, and user interactions. - https://owasp.org/www-project-top-10-for-business-logic-abuse/
9. Non-Human Identities Top 10 (2025) - The most critical risks non-human identities present to organizations, ranked by exploitability, prevalence, detectability, and impact. - https://owasp.org/www-project-non-human-identities-top-10/
10. MCP Top 10 (2025) - Structured security guidance for Model Context Protocol implementations as AI systems integrate into software supply chains and enterprise applications. - https://owasp.org/www-project-mcp-top-10/
11. Top 10 Drone Security Risks (2024) - Adapts the known security vulnerabilities from the mobile and web application domain to the specific context of drones. - https://owasp.org/www-project-top-10-drone-security-risks/
12. Data Security Top 10 (2025) - Data is the most important asset many organizations possess, yet often data security is not the top priority. - https://owasp.org/www-project-data-security-top-10/
13. Citizen Development Top 10 (2025) - Security risks introduced by citizen developers building on low-code platforms such as Power Platform, SAP, ServiceNow, and Salesforce. - https://owasp.org/www-project-citizen-development-top10-security-risks/
14. Machine Learning Security Top 10 (2023) - An overview of the top ten security issues in machine learning systems; currently in draft and modified frequently. - https://owasp.org/www-project-machine-learning-security-top-10/
15. Top 10 Client-Side Security Risks (2022) - Browser-side applications are frequently a complex combination of custom HTML, CSS, and JavaScript, leveraging numerous third-party libraries and services. - https://owasp.org/www-project-top-10-client-side-security-risks/
16. Desktop App Security Top 10 (2021) - A standard awareness document for the most critical security risks to desktop and thick-client applications, covering Windows and *nix. - https://owasp.org/www-project-desktop-app-security-top-10/
17. Top 10 Privacy Risks (2021) - Provides a top 10 list for privacy risks in web applications and related countermeasures. - https://owasp.org/www-project-top-10-privacy-risks/
18. Docker Top 10 (2019) - Ten bullet points to plan and implement a secure Docker-based container environment. - https://owasp.org/www-project-docker-top-10/
19. Serverless Top 10 (2018) - Educates practitioners on the consequences of the most common serverless application security vulnerabilities and how to identify and protect against them. - https://owasp.org/www-project-serverless-top-10/
20. IoT Top 10 (2018) - Helps manufacturers, developers, and consumers understand the security issues associated with Internet of Things devices. - https://owasp.org/www-project-internet-of-things/
21. Operational Technology Top 10 (2025) - A comprehensive list of the top security risks and vulnerabilities specific to Operational Technology (OT) environments. - https://owasp.org/www-project-operational-technology-top-10/
22. Agentic Skills Top 10 - Documents the 10 most critical security risks in agentic AI skills across all major AI agent platforms. - Status: AST01-AST10 drafted, incidents tracked through July 2026, Incubator, targeting v1.0 Q3 2026 - https://owasp.org/www-project-agentic-skills-top-10/


## Count

21 Active, real OWASP Top Ten projects. 3 more are technically live pages but dead in substance. 1 is officially inactive.

## Notes on accuracy

- Project names, versions, and status classifications (active / in development / dropped / inactive) are as supplied when this catalog was compiled, and were not independently re-verified against OWASP's site at read time.
- Descriptions are pulled from each project's own page, using a scope-statement sentence rather than an opening announcement where the page led with the latter.
