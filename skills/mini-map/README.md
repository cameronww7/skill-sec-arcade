# 🧭 Mini-Map

*A cabinet in the [sec-arcade](../../): insert coin when you want a 50-line context file other skills can load instead of the full dungeon map.*

![Output](https://img.shields.io/badge/output-%E2%89%A450_lines-brightgreen)

A Claude Code skill that condenses an existing [`dungeon-crawl-threat-map`](../dungeon-crawl-threat-map) report into a hard-capped, ~50-line `MINI_MAP.md`: application overview, identity and session handling, security hardening, trust boundaries and data flow, business logic invariants, and known risk areas. Written for other skills to load as background context, not for a person to read as a standalone report.

## Overview

A finding-review skill or a remediation pass doesn't need the whole threat model to do its job, it needs the handful of facts that would change the answer: how does this app authenticate people, is there SSO, where do trust boundaries sit, what business rule would a fix have to preserve. Loading the full `THREAT_MODEL.md` every time is slow and mostly irrelevant to any one question. This skill produces the condensed version once, and other skills read that instead.

Run it, get back:

- A short overview of what the system is and its core stack
- Identity & Session: auth method/provider (including SSO), authorization model, session/token lifecycle notes if flagged
- App Hardening: secrets handling, crypto notes, dangerous defaults if flagged
- Trust Boundaries & Data Flow: where data crosses a boundary, where untrusted input enters and reaches a sink
- Business Logic Invariants: abuse-relevant workflows only (race conditions, workflow-bypass, parameter manipulation), omitted entirely if none were flagged
- Known Risk Areas: the highest-priority items from the source threat model
- Pointers to the full `THREAT_MODEL.md`, and `CARTRIDGE_SCAN.md`/`DEAD_WEIGHT_REPORT.md` if those exist too

## Prerequisites

- [Claude Code](https://claude.com/claude-code) installed and configured
- An existing `.SEC-Arcade-save_states/THREAT_MODEL.md` in the target repo, generated by [`dungeon-crawl-threat-map`](../dungeon-crawl-threat-map). If it's missing, this skill offers to generate it first.
- Run from inside the repository being summarized.

## Installation

This skill ships as part of the [`sec-arcade`](https://github.com/cameronww7/skill-sec-arcade) Claude Code plugin.

### Option 1: Install the whole arcade (recommended)

```bash
/plugin marketplace add cameronww7/skill-sec-arcade
/plugin install sec-arcade
```

### Option 2: Just this skill

```bash
# personal, applies in every project
git clone --depth 1 https://github.com/cameronww7/skill-sec-arcade.git /tmp/sec-arcade
cp -r /tmp/sec-arcade/skills/mini-map ~/.claude/skills/
mkdir -p ~/.claude/sec-arcade-standalone
cp -r /tmp/sec-arcade/references ~/.claude/sec-arcade-standalone/

# project-level, this repo only
mkdir -p .claude/skills
cp -r /tmp/sec-arcade/skills/mini-map .claude/skills/
```

Note: if installing standalone, also copy `references/save-states.md` from the arcade repo per the command above, and copy [`dungeon-crawl-threat-map`](../dungeon-crawl-threat-map) too, this skill depends on its output. `SKILL.md` points at `references/save-states.md` via `${CLAUDE_PLUGIN_ROOT}/references/...`, an environment variable only set automatically for a full plugin install. For this standalone copy to work, set it yourself before launching Claude Code, e.g. add `export CLAUDE_PLUGIN_ROOT=~/.claude/sec-arcade-standalone` to your shell profile.

## Usage

Open Claude Code inside a repo that already has a threat model, then ask directly:

```
Build a quick context file for this app
```

```
Condense the threat model so other skills can use it
```

If no threat model exists yet, the skill will ask whether to generate one first.

### Example output

```
# Mini-Map: payments-service

_Condensed from `.SEC-Arcade-save_states/THREAT_MODEL.md`, generated 2026-08-29, target repo at commit a1b2c3d._

## Overview
Node/Express payments API used by the mobile app and internal admin tools.

## Identity & Session
- Auth: OAuth2 via internal SSO provider, JWT bearer tokens.
- Authorization: role-based, enforced at the API gateway and again per-handler.
- Session/tokens: no rotation on refresh-token reuse, flagged in threat model.

## App Hardening
- Secrets: pulled from a secrets manager at boot, none hardcoded.
- Crypto: password hashing via bcrypt, no issues flagged.

## Trust Boundaries & Data Flow
- Public internet -> API gateway -> internal admin routes, no separate boundary control on admin routes today.

## Known Risk Areas
- No auth guard on `/admin/export`, unlike every other `/admin/*` route.

## Full Reports
`.SEC-Arcade-save_states/THREAT_MODEL.md`, `.SEC-Arcade-save_states/CARTRIDGE_SCAN.md`
```

## Limitations

- Only as good as the threat model it condenses. If `dungeon-crawl-threat-map` missed something, this file won't have it either.
- Not a substitute for the full report when a human needs to actually review the reasoning behind a finding, this is for quick machine context, not deep understanding.
- Overwrites the previous `MINI_MAP.md` on every run, it isn't versioned, `git diff` it if you want to see what changed.
